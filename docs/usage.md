## 1. 记录工作时间

在“工作计时”页面选择“正式工作”或“摸鱼/学习”。开始成功后显示当前计时时长。同一服务只允许一个进行中的计时，其他设备看到的是同一条记录。

点击“结束”打开确认框。默认结束时间是打开确认框时的时间；如果忘记及时停止，可以把它提前到实际结束时间，并查看保留与扣除的时长。不能早于开始时间。当前界面也不允许晚于打开确认框时捕获的时间；后端另以收到请求时的服务器时间作上界校验。

点击确认才保存结束时间，取消或关闭确认框会继续计时。关闭浏览器也不会自动结束；重新打开页面后会根据服务器记录恢复显示。

计时显示以服务器时间校准，设备时间偏差不会直接成为计时依据。显示每秒更新，服务器状态约每 15 秒同步一次，页面重新可见时也会同步。连接失败时显示提示并禁用新的计时操作，已知的计时仍继续显示；恢复连接后重新校准。

## 2. 查看历史与编辑笔记

点击日历中的日期，查看当天时间分布与记录明细。蓝色表示正式工作，绿色表示摸鱼/学习；日历总时长合计两类记录，按小时显示一位小数。

一条跨午夜的计时会在相关日期分别显示当天的片段，数据库中仍是一条记录。日期按浏览器本地时区划分，不同设备时区不同时，按日统计可能不同，但保存的起止时间戳相同。

点击记录的笔记区域，输入后保存；保存失败时弹窗内文字保留。删除记录需要确认，进行中的记录必须先结束。跨日片段共享同一个记录 ID，因此编辑笔记影响整条记录，删除也会删除整条跨日计时。

## 3. 用任务面板推进一个问题

| 层次 | 表示什么 | 示例 |
| --- | --- | --- |
| 任务 | 希望完成的目标 | 复现实验 |
| 问题节点 | 推进目标时需要解决的问题 | 准确率偏低 |
| 待办 | 可以执行、完成后勾选的行动 | 检查输入归一化 |
| 进度记录 | 这项待办的尝试、结果与下一步 | 已核对均值和方差，下一步检查测试集预处理 |

1. 点击“新建任务”，填写标题、说明和状态。左侧可按任务标题/说明搜索，并按状态筛选。
2. 选中任务，点击“添加问题节点”，填写问题标题、说明与状态。同一任务下的节点是平级列表。
3. 选中节点，在“待办清单”输入行动，按 Enter 或点击“添加”。新待办自动展开，方便接着记录进度。
4. 在具体待办内部填写日志，点击“记录进度”。日志按新增顺序倒序显示，并带有保存时间。
5. 行动完成后勾选待办；日志仍可查看和继续追加。需要回看时点击“展开进度”，不看时收起。

## 4. 状态和完成比例

| 对象 | 状态/完成方式 | 会不会自动改变上级状态？ |
| --- | --- | --- |
| 任务 | 待办、进行中、已完成 | 手动设置 |
| 节点 | 待解决、处理中、已解决 | 不会自动完成任务 |
| 待办 | 勾选完成或取消勾选 | 不会自动解决节点 |

节点里的进度条表示“已完成待办数 / 待办总数”。任务卡片显示“已解决节点数 / 节点总数”。这些是数量统计，不是根据日志文字推断出的工作进度。

编辑任务和节点的标题、说明后需要点击保存。节点状态下拉框和待办复选框直接发起保存请求。进度日志当前支持追加和删除，没有编辑已保存日志的功能；要更正可以追加说明，或删除后重新记录。

## 5. 保存、删除和多端同步

| 操作或情形 | 实际行为 |
| --- | --- |
| 切换节点、折叠待办 | 当前页面中的新待办输入与日志草稿保留，展开状态也保留 |
| 日志写入请求失败 | 显示错误，不清空草稿 |
| 刷新或关闭页面 | 未提交草稿和展开状态丢失；已保存数据仍在 |
| 删除一条进度日志 | 只删除该条日志 |
| 删除待办 | 确认后删除待办及其全部日志 |
| 删除节点或任务 | 确认后删除其下属节点、待办和日志 |
| 多设备使用 | 读取同一服务的共享数据；任务面板激活且页面可见时约每 15 秒刷新 |

打开任务编辑弹窗或正在保存时，面板暂停自动轮询；保存后重新读取数据，也可手动点击“刷新”。不同设备编辑同一对象时，后保存的字段覆盖先保存的字段，没有编辑锁或冲突合并；独立追加的日志各自成为一条记录。

“写入成功”与“随后刷新成功”是两个步骤。若写入成功而刷新失败，面板会提示加载失败，已写入的数据仍在服务器；恢复后点击刷新确认。若请求因网络中断而没有收到响应，也可能已经写入，重试前可先刷新核对。

## 6. 升级旧数据与当前边界

原版本直接归在节点下的日志，升级时会迁入该节点新增的“历史进度（原节点记录）”待办。原文、时间和日志 ID 保留；不会猜测它属于哪条现有待办。历史待办初始未完成，可自行勾选；没有旧日志的节点不会新增历史待办。详见[数据库迁移](database.md#6-初始化与迁移)。

目前没有任务与计时的工时关联、账号隔离、离线保存队列、节点自由连线或递归子节点。所有持久数据都由你所连接的后端保存；换一个数据库或另一台独立后端，不会自动带入原来的记录。
